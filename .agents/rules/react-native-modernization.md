# React Native Modernization Agent Rules

These rules govern all agent workflows and subagents working on `react-native-template-ts-plus`.

## 1. Environment & Runtime Standards
- **Java Home:** Always execute Android/Gradle commands with `JAVA_HOME=/usr/lib/jvm/zulu-17` (Zulu OpenJDK 17).
- **Node Engine:** Baseline is Node 22 LTS / Node 20+.
- **Package Managers:** Support Yarn 1.x (classic) and npm.

## 2. Template Scaffold & Placeholder Hygiene
- **Placeholder Name:** The app placeholder name is `HelloWorld` (configured in `template.config.js`). Never hardcode custom project names inside `template/`.
- **Scaffold-First Protocol:** When modernizing the native layers, use a clean baseline generated by `@react-native-community/cli` and apply additions additively. Avoid carrying forward legacy workarounds (e.g. Flipper, manual APFS OpenSSL links).
- **Package Integrity:** The published root package exports the template metadata. `template/` is the template body. Never mix root repo dependencies with template app dependencies.

## 3. Architecture & Ecosystem Standards
- **Architecture:** Target React Native `0.87.x` with New Architecture enabled natively.
- **Dependency Compatibility:** All retained libraries must support New Architecture (Fabric / TurboModules) and modern React Native presets.
- **TypeScript First:** All template source code resides in `template/src/` with `~/` alias import support.

## 4. History & Verification Discipline
- **Atomic Commits & Logs:** Keep changes bounded per phase.
- **Decision Records:** Document significant dependency or architectural decisions in `docs/adr/`.
- **Verification Gates:** Run lint, type-check, and smoke app generation at every major phase boundary before finalizing changes.
